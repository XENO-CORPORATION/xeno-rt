# xeno-rt v0.2.0

v0.2.0 is the first native CPU/CUDA checkpoint for xeno-rt. It preserves the
GGUF CPU runtime and adds a real CUDA execution backend with resident model/KV
state for the documented support matrix.

## Highlights

- Native CUDA GGUF decode for compatible dense models and listed weight types.
- CUDA-only Qwen2/Qwen3 SafeTensors support for dense and selected packed 4-bit
  layouts.
- F32, Q8, KQ4/VQ8, and policy-adaptive KV modes.
- CUDA Graph support, prefix caching, bounded scheduling, decode batching, and
  runtime resource telemetry.
- CPU/CUDA/external benchmark comparison with structured JSON evidence.
- Expanded model geometry, OpenAI-compatible server lifecycle, vision, and
  binding workspaces.
- Portable locked builds and hardened release/security automation.

## Compatibility

- CPU-only builds remain supported and are the default.
- GGUF remains the required portable CPU model format.
- `auto` may select compatible CUDA and falls back to CPU for GGUF when CUDA
  initialization fails.
- Explicit `cuda` requests fail explicitly if the build, model, or device is
  unsupported.
- Existing documented completion/chat routes remain available.

See [Supported Models](../SUPPORTED_MODELS.md), [API](../API.md), and
[Configuration](../CONFIGURATION.md) before deployment.

## Known Limitations

- SafeTensors decode is CUDA-only and limited to documented Qwen2/Qwen3 layouts.
- The HTTP server has no built-in inbound authentication or TLS; it binds to
  localhost by default.
- C/Python packaging and image-task routes remain experimental.
- CUDA support is beta and bounded by the validated architecture/format matrix.
- XENO R2/Hub desktop publication is blocked until the product's installer vs
  CLI/archive delivery contract is resolved.

## Validation and Artifacts

The GitHub release is expected to contain Linux x86-64 and Windows x86-64
CLI/server archives, per-archive SHA-256 files, a combined `SHA256SUMS`, SPDX
SBOMs, and GitHub provenance/SBOM attestations.

The stable tag was approved after the release workflow dry-run passed and the
Linux and Windows release candidates were manually inspected.

## Upgrade Notes

- Default builds no longer force `target-cpu=native`; local native benchmark
  builds must set `RUSTFLAGS` explicitly.
- `Cargo.lock` is part of the binary workspace release contract.
- Consult runtime status for the active backend rather than assuming `auto`
  selected CUDA.
